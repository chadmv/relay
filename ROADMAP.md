Relay is a distributed task/render-farm orchestrator: three Go binaries (relay-server =
HTTP + gRPC + scheduler with an embedded React/Vite SPA; relay-agent worker that holds one gRPC
stream and runs each task as a subprocess; the relay CLI), plus an MCP server and a Perforce
source-provider. Hardening is complete - the 2026-06-10 review's findings are closed and the
seven cross-cutting invariants in CLAUDE.md are enforced and well-tested. They are written in
backend terms but hold across the stack: the generation-ordering rule was rediscovered as a
frontend bug, so `web/` changes are in scope for them too.

The active phase is the embedded web SPA build-out, governed by the `design_handoff_relay_holo`
"Holo" direction (the hi-fi `hifi3-holo-pages.jsx` layer is authoritative; `reference/` is
structure-only). The relayout is done and every surface sits on the shared
`web/src/components/holo` primitives, so what remains is net-new surfaces and backend depth, not
styling. Two rules govern the work: omit data the backend cannot supply rather than fabricating
it, and file the enabler instead; and extract a shared primitive before its third consumer.
Remaining, in rough order: the jobs filter/lane/timeline views, the job-actions wiring, and the
backend enrichers and small endpoints those need. The web-enabler endpoint trio is now fully
shipped, so no backend item currently blocks a frontend one. MCP, agent-runtime and store/schema
items fill in behind. Accessibility and shared-primitive debt is the most reprioritized category
in recent refreshes.

## Now / Next / Later

### Now
- [reconcileRunningTasks compares wire task ids against canonical ones](docs/backlog/bug-2026-08-15-reconcile-compares-wire-task-ids-against-canonical-ones.md) - bug, medium; **new 2026-08-15, and it leads because it is silent and fires on every reconnect.** Found by carrying a review finding one function outward: `serverSet` is keyed on the canonical `uuidStr(t.ID)` but looked up with the raw wire `rt.TaskId`. `pgtype.UUID.Scan` accepts uppercase hex, the 32-char undashed form, and a form with non-hyphen separators - all parse, none match. The task therefore **bypasses the epoch comparison entirely**, is cancelled, and is requeued by the second loop. No error, no log line, every reconnect.
- [A stale running task is never terminated by the coordinator](docs/backlog/bug-2026-08-14-no-coordinator-watchdog-on-a-stale-running-task.md) - bug, medium. `timeout_sec` is enforced only in `internal/agent/runner.go` and `timed_out` is written only by `handleTaskStatus`, so the timeout lives entirely on the untrusted side; `GraceRegistry` covers disconnect only and `failClaimedTask` covers dispatch failure only. An agent that simply never reports terminal holds its assignment, its worker slot, and an unbounded `task_logs` write channel forever. A timeout enforced solely by the party it constrains is not a timeout.
- [An end-to-end browser harness for the web SPA](docs/backlog/idea-2026-06-03-web-e2e-harness.md) - idea; five sessions of evidence, and the last three iterations sharpened its scope rather than its priority. Diffs that change what is *rendered* need a browser; diffs that change what is *wired* were better served by mutation testing. This item is for the former.

### Next

## What moved

- **The attacker-driven agent-ingest log flood is closed.** `taskLogErrLimiter` is replaced by `ingestLogLimiter`: a dedupe map with a time-based re-arm plus a **per-connection token bucket keyed on nothing**, which is the bound. The task-status path, which had no limiter at all, is now under the same budget. Unit 487 -> 491 top-level; worker integration 75 -> 100; `-race` green.
- **For the second consecutive iteration the item was useful and its prescribed remedy would have closed nothing.** It said key on the authenticated worker and named reset-instead-of-suppress at 1024 as the defect. But `epoch` was the map **value**, not part of the key, so one fixed task id with a varying `chunk.Epoch` produced one log line per message from a map of exactly **one entry** - never growing, never reaching the cap, never calling `reset()`. So 1024 entries were already bounded; the unbounded resource was the process-global `log` mutex. **An item names the mechanism it saw, not necessarily the one that binds.**
- **The design story changed twice, and the durable form is now a doc comment.** The spec's headline mutation claim was refuted by the plan (64 varying epochs are still 64 unreported events requesting 64 tokens), and a lens later confirmed it empirically by rewriting the limiter that way and watching the flood tests still pass. **The composite key is required because one map holds several kinds, NOT because it closes the flood. The bucket closes the flood.**
- **The centrepiece finding: the file argued against its own bug two comments later.** It rejected permanent suppression because it "has NO TIME-BASED RECOVERY" - for the 128-key case it does not reach - while three of its four kinds had exactly that property without ever approaching 128. Measured at one failing message per second for seven simulated days: **one line**, bucket full the whole time. That is this project's own recorded "a recovery bound must be time-based" rule, rediscovered inside code whose comment states it correctly. **Stating a principle in a comment is not the same as checking the code against it** - the ten-iteration wrong-prose streak inverted, and strictly worse, because right prose immunizes the code beside it from re-derivation.
- **`pgtype.UUID.Scan` does not constrain the bytes it accepts**, found independently by two lenses with probes: for a 36-byte input it discards indices 8, 13, 18 and 23 without checking they are hyphens. That made the wire id a log-injection sink (one event rendering as five physical lines, reachable *without owning the task*) and a **2^32-way dedupe-key escape**. One fix - the canonical re-encoded id - closed both. **Carrying that finding one function outward found a new bug**, now leading Now: `reconcileRunningTasks` compares wire ids against canonical ones and silently cancels and requeues the task on every reconnect.
- **A test seam was rejected for destroying the behavioural RED.** The spec accepted a throwaway-limiter-per-call wrapper to keep 41 call sites byte-identical; the planner refused it, because the headline tests would then be written against a symbol that does not exist at HEAD - so the "RED" is a compile error and **the test that goes green is not the test that was red**. It also found the spec's isolation test vacuous: it asserted only that two separately-constructed structs are independent, which is true of any struct.
- **Every stage found errors in the stage before it, and the conductor was a stage.** Spec refuted the item; plan refuted six spec claims; the engineer found five plan errors including a required test that was RED on both sides; the lenses found what all of that missed; and **the conductor's remediation brief carried two defects of its own** - an assertion that could never pass, and a regression claim over-scoped by one third - both caught by the engineer. That lane now gets the same verify-before-dispatch discipline as the spec and plan lanes.
- **A cross-lens disagreement settled by a third measurement.** Two lenses disagreed on a figure in a comment; `captureLog` calls `log.SetFlags(0)`, so one lens's number could not reproduce and the other's was exact. Both quantities are now in the comment, **labelled**, so it cannot be misread again.
- **Five filed, one closed; open count 78 -> 82.** The scope is stated honestly rather than as "closes the hole": per-connection is only a bound if connections are bounded, and suppression is now silent, so a flood is invisible rather than noisy.

## API authorization, auth & account lifecycle (api-auth)

1. [gRPC connection and stream admission is unbounded](docs/backlog/bug-2026-08-15-grpc-connection-admission-is-unbounded.md) (bug, medium) - **new 2026-08-15**, and the direct residual of the ingest-log budget that just shipped. `cmd/relay-server/main.go` sets `KeepaliveParams` only: `MaxConcurrentStreams` is unset so grpc-go's `MaxUint32` default applies, and there is no `EnforcementPolicy`, no `MaxConnectionAge` and no interceptor. [Cursor values are not validated against the sort key's kind](docs/backlog/bug-2026-08-13-cursor-value-kind-not-validated.md) (bug, medium) - **new 2026-08-13**, found independently by two review lanes and probed. `parsePage` compares a cursor's sort field to the resolved sort but never its **value kind** against `SortKind` (`internal/api/pagination.go`), so a null- or text-valued cursor on a timestamp key decodes to a zero time: the DESC arm returns an empty page while `total` still reports N - the exact "footer states a number the caller cannot page to" failure the SQL comments guard against, reached by a route SQL cannot defend. Affects every paginated endpoint identically.
