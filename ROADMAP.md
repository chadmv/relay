Relay is a distributed task/render-farm orchestrator: three Go binaries (relay-server =
HTTP + gRPC + scheduler with an embedded React/Vite SPA; relay-agent worker that holds one gRPC
stream and runs each task as a subprocess; the relay CLI), plus an MCP server and a Perforce
source-provider. Hardening is complete - the 2026-06-10 review's findings are closed and the
seven cross-cutting invariants in CLAUDE.md are enforced and well-tested. They are written in
backend terms but hold across the stack: the generation-ordering rule was rediscovered as a
frontend bug, so `web/` changes are in scope for them too.

The active phase is the embedded web SPA build-out, governed by the `design_handoff_relay_holo`
"Holo" direction (the hi-fi `hifi3-holo-pages.jsx` layer is authoritative; `reference/` is
structure-only). The relayout is done and every surface sits on the shared
`web/src/components/holo` primitives, so what remains is net-new surfaces and backend depth, not
styling. Two rules govern the work: omit data the backend cannot supply rather than fabricating
it, and file the enabler instead; and extract a shared primitive before its third consumer.
Remaining, in rough order: the jobs filter/lane/timeline views, the job-actions wiring, and the
backend enrichers and small endpoints those need. The web-enabler endpoint trio is now fully
shipped, so no backend item currently blocks a frontend one. MCP, agent-runtime and store/schema
items fill in behind. Accessibility and shared-primitive debt is the most reprioritized category
in recent refreshes.

## Now / Next / Later

### Now
- [relay logs prints nothing for any job](docs/backlog/bug-2026-08-25-relay-logs-prints-nothing-envelope-drift.md) - bug, high; **new**, and broken since `a90c727` on 2026-05-08 - three and a half months. `printTaskLogs` decodes the logs endpoint into a bare slice; the handler has returned `{items, next_seq, total}` since that commit. The decode error is real and `Client.Do` reports it faithfully; `printTaskLogs` discards it as "best-effort", which is what turned a shape mismatch into silent no-output. Ship with the item below - same endpoint, same drift, and fixing one client while leaving the other is how this survived a fix already aimed at it.
- [Python SDK task_logs() iterates the pagination envelope keys](docs/backlog/bug-2026-08-25-python-sdk-task-logs-iterates-envelope-keys.md) - bug, high; **promoted from Next this refresh, to sit beside the item above rather than a tier below it.** They are one defect in two clients: the logs endpoint has returned `{items, next_seq, total}` since `a90c727`, and both still read it as a bare list. Iterating a dict yields its KEYS, so the SDK validates the strings `"items"`, `"next_seq"`, `"total"` as log records. It is also an INCOMPLETE FIX - [python-sdk-list-pagination-envelope](docs/backlog/closed/bug-2026-05-26-python-sdk-list-pagination-envelope.md) closed `fixed` on 2026-06-03 claiming every paginated endpoint had an SDK method, three and a half weeks after this one became paginated. Must land with (or immediately before) the item below.
- [A permanently un-fireable schedule is invisible](docs/backlog/bug-2026-08-23-unfireable-schedule-is-invisible.md) - bug, medium; **paired with the item above, and it is why that item is dangerous alone.** A stored spec that stops validating advances `next_run_at` forever with only a log line - no `last_error` column, no failure field - so `retries` bounding retroactively disabling schedules would be silent.
