> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take the sort caret out of every sortable header's accessible name, stop `TasksTable`
advertising a selection model `role="table"` does not have, name the one unnamed table and pin the
two panel-title duplications, and collapse eleven table frames and eleven header spacing strings

`Panel.tsx`, the eleven `Table` consumers, `RevokedWorkersTable.tsx`, `WorkerDetailPage.tsx`,
`JobDetailPage.tsx`, their vitest files, and one new describe block in `web/e2e/keyboard.spec.ts`.
No new dependency, no API change, no new query key.

**Tech Stack:** React 18, TypeScript (strict, `noUnusedLocals`), Tailwind v4 via
`@tailwindcss/vite`, vitest 4 + jsdom + @testing-library, Playwright 1.62 (chromium + a
`@webkit`-tagged subset).

## Conventions that bind every task

- **Run every `npm` / `npx` command from `web/`.** The plan writes `cd web && ...` each time.
- **Never `git checkout -- <file>` to undo a mutation.** Every mutation step in this plan is
  "edit the line, run the test, edit the line back". A `git checkout` would discard the
  uncommitted test you are trying to prove.
- **Never spell a Tailwind utility class in a comment or a test string you add under `web/`.**
  Tailwind v4's scanner reads source files on disk with `pattern: '**/*'` over the Vite root, so a
  class-shaped substring in prose emits CSS. Name the CSS property instead. (This plan lives in
  `docs/`, a sibling of `web/`, so its own class literals are not scanned.)
- **Cite by symbol or by a findable phrase, never by `File.tsx:123`,** in any comment you write.
- **ASCII only in anything you author.** Where a test needs one of the caret code points, write the
  four-character escape `\u25BC` (down) or `\u25B2` (up), which the compiler expands. Do not paste
  the raw character.
- **Hyphens only** in prose, never an em dash or an en dash.

type TableRowProps = Omit<ComponentPropsWithoutRef<'div'>, 'role' | 'dangerouslySetInnerHTML'>

// focusability semantics are the reason the other describe in this file exists, so
// this one pays for the second engine too.
//
// DEFAULT VIEWPORT. The other describe's test.use is scoped to that describe; this
// one deliberately measures the surface at the size the screenshots use.
test.describe('job-detail task selection @webkit', () => {
  test('Enter on a task control moves the sole aria-current mark, and no row is aria-selected', async ({ page }) => {
    const seed = readSeed()
    await page.goto(`/jobs/${seed.jobId}`)
    await expect(page.getByRole('heading', { name: seed.jobName, level: 1 })).toBeVisible()

    const table = page.getByRole('table', { name: 'Tasks' })
    await expect(table).toHaveCount(1)
    // aria-selected is not surfaced under role="table". Asserted in the browser as
    // well as in jsdom because this is the advertisement the lane exists to remove.
    await expect(table.locator('[aria-selected]')).toHaveCount(0)

    const current = table.locator('[aria-current="true"]')
    await expect(current).toHaveCount(1)
    const startingName = ((await current.textContent()) ?? '').trim()

    // Target a task that is NOT already marked. A test that re-selects the default
    // selection passes against a mark hardcoded onto the first row.
    const target = ['alpha', 'beta', 'gamma'].find((n) => n !== startingName)
    expect(target, `the marked task was ${JSON.stringify(startingName)}, which is not one of the seeded tasks`).toBeTruthy()
    const targetButton = table.getByRole('button', { name: target as string, exact: true })
    await expect(targetButton).toHaveCount(1)

    await page.evaluate(() => (document.activeElement as HTMLElement | null)?.blur())
    let reached = false
    for (let i = 0; i < 80 && !reached; i++) {
      await page.keyboard.press('Tab')
      reached = await targetButton.evaluate((el) => el === document.activeElement)

})

Noticed while planning; out of this lane's scope; **not filed** - for the conductor to accept or
reject.

- **`ScheduleRunsPanel` is a fourth panel-title duplication.** It renders `<Panel title="Recent
  runs">` and `<Table label="Recent runs">`, two literals kept equal by hand, in one file. The
  `data-panel-title` hook this lane adds makes it a two-line fix plus one structural test on
  `ScheduleDetailPage`, in the same shape as Task 2. The spec scoped the naming work to
  `WorkerDetailPage`'s two panels, so it stays out here.
- **The Spec/Log tabs have no tabpanel.** `JobDetailPage` renders a `role="tablist"` and two
  `role="tab"` buttons with `aria-selected`, and the panel below is a plain `GlassPanel` with no
  `role="tabpanel"`, no `id` and no `aria-controls`. Same advertised-but-unfulfilled-contract shape
  as the UserMenu precedent, on a different surface.
- **No automated a11y rule engine under `web/`.** `aria-selected` under `role="table"` is a rule
  axe-core ships, and so is `scrollable-region-focusable`, which this codebase found by review
  rather than by tooling. An axe pass wired into the existing Playwright harness would have caught
  the TasksTable item at authoring time.
- **Row density still diverges from the hi-fi.** The hi-fi's top-level list rows are 10px/18px;
  after this lane the app's are 18px horizontal and 8px vertical. Closing the vertical half is a
  visible change that belongs with a wider density pass.
- **`WorkersTable` has no populated e2e coverage of any kind**, a special case of the known slice-1
  limit, and the reason this lane's most visible change ships unwatched by the harness.
