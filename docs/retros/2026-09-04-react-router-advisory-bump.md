# Session Retro: 2026-09-04 - react-router Advisory Bump

**TL;DR:** The SPA shipped a router version with known published vulnerabilities, and the fix was
a one-command version bump with no code change. That part took minutes. The rest of the work was
finding out that the backlog item describing the problem was wrong about it in three separate ways
- wrong about how many vulnerabilities there were, wrong about which one was serious, and wrong
about whether the serious ones could happen here at all. The bump is still the right thing to do.
It is just hygiene rather than the urgent security fix the item advertised, and every attempt to
correct the item introduced a fresh wrong claim of its own.

## Handoff

Lane A of a six-item batch over ROADMAP.md's Now section. Closed
[[bug-2026-09-03-react-router-production-advisories]]. Two commits: the bump `543890e`, the close
`69487f8`.

react-router and react-router-dom 7.16.0 to 7.18.3, lockfile only. The fix line sits inside the
existing `^7.1.1` range so `web/package.json` is untouched, and `react-router` is not a direct
dependency - it arrives through `react-router-dom`. Diffstat 7 insertions / 7 deletions.

**The numbers, on the axis they are actually on.** `npm audit`'s `metadata.total` counts affected
PACKAGES, not advisories, and every figure in this item's history is on one axis or the other.
Before the bump: three packages (`react-router` high, `react-router-dom` moderate, `undici` high),
with `react-router`'s own `via` array holding five advisories. After: one, `undici`, which
`--omit=dev` shows is absent from the production tree and which nothing under `web/src` imports.

**GHSA-wrjc-x8rr-h8h6, which the item's title calls "a high open redirect", is rated MODERATE.**
`react-router`'s two highs are GHSA-chx6-hx7r-mcp5 (DoS via inefficient route matching) and
GHSA-qwww-vcr4-c8h2 (RSC mode CSRF bypass).

**Reachability decides whether any of it mattered, and it cuts the other way.** React is pinned at
`^18.3.1`; RSC mode needs React 19 plus a `react-server-dom-*` runtime, so the two RSC advisories
are structurally uninstallable here - one of them a high. `web/index.html` is an empty `div#root`
with one module script, so there is no hydration payload for the SSR `deserializeErrors` advisory.
That leaves the moderate open redirect and the route-matching DoS, and neither has a live sink:
every navigation target in the SPA is a literal or a literal-prefixed template with a
server-supplied id, and relay-server does no react-router matching at all (`internal/api` uses a
plain `http.NewServeMux`; `web/embed.go` prefix-matches `/v1/`).

Verify: 189 test files / 1504 tests, `tsc -b` clean, `npm run build` green, Playwright 88 passed
(51.6s) chromium and webkit under the e2e lock, zero skips. `ROADMAP.md` still carries the old
"high open redirect" wording in two places; that is left to the batch's closing roadmap refresh.

## What Was Built

Nothing was built. One `npm update` and a lockfile diff. Recording that plainly matters, because
the value of the session is entirely in what was checked, not in what was written.

## Key Decisions

- **Correct the item's severity claim rather than inherit it.** The commit message and the item's
  `## Resolution` both had to be rewritten. A wrong claim in a closed backlog item is read by
  future sessions as settled fact.
- **State the reachability finding even though it argues DOWN the priority of the work being
  shipped.** The bump is right; overstating why would have made the record worse.
- **Leave `ROADMAP.md` alone.** It is regenerated by `/roadmap`, and two other entries in it also
  point at files this batch moves. A hand edit would be undone by the refresh.

## What Went Wrong and What Changes

**The implementing agent read the advisory list and still reported "nothing in the item needed
correcting".** It printed the five advisory records - including the `severity: "moderate"` field
on the one it then called high - and drew no conclusion from them. Having the evidence in front of
you is not the same as checking the claim against it. The conductor caught it only by re-reading
the raw audit JSON.

**Then the correction itself was wrong, twice, in the same paragraph** - and this is the more
useful lesson, because the first mistake is ordinary carelessness while this one is structural.
The review found both:

- The correction called the roadmap's "11" a miscount. **It was not.** Lane T measured 11 affected
  packages at its own HEAD and its own toolchain bump cleared eight of them, leaving exactly the
  three measured here. The arithmetic closes with nothing left over. The correction retired a good
  measurement as sloppy and left the real error - both records say "advisories" where npm counted
  packages - in place.
- The correction wrote "the two HIGH advisories were X and Y" without scoping it to
  `react-router`. Across the whole audit there were six highs, because `undici` carried four more.
  Worse, the sentence sat two paragraphs below "three affected packages (moderate 1, high 2)", so
  the definite article invited the reader to map that pair onto the package rollup - which is
  `react-router` and `undici`, a different pair entirely. **A sentence written to correct a
  per-package-versus-total conflation committed one, using the same numeral.**

The existing lesson that a correction authors a fresh unchecked claim gains a sharper instance
here: the fresh claim was in the same idiom as the error being corrected. When rewriting a count,
name the axis in the same sentence as the number, and check whether the figure you are calling
wrong was right on some other axis before retiring it.

**A green suite bounded less than it looked like it did.** 1504 unit tests passed, but
`BrowserRouter` appears only in `App.tsx` while 59 test files use `MemoryRouter`, so the suite
never constructs a browser history and never exercised the URL normalization 7.18.0 changed. The
five Playwright specs are the only tests that touch a real URL bar, and their targets are clean
literals. The suite says the happy paths still work; it does not retire the normalization change,
and the PR now says so.

**Two process notes.** The implementing agent's e2e run was backgrounded and outlived the agent,
so the lane reported "finished" with its headline verification still in flight; the conductor
established it was alive rather than dead by observing the e2e lock directory and the listening
port. And bash double-quoting broke a `python -c` twice: inner double quotes terminate the string
and backticks command-substitute. Prose containing quotes goes into a quoted heredoc written to a
file, then gets read by path - or is written with a file tool rather than through the shell at all.
